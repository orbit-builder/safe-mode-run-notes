# Safe Mode approval loop with Nitrosend and mailschema: run notes

- **Environment:** Node v20.19.2, npm 11.21.1, Linux. Installed with `npm i @nitrosend/sdk@0.11.10 mailschema@0.3.2`. Commands run with `npx mailschema@0.3.2`.
- **Setup (REST, no browser):** `POST /v1/signup`, then `POST /v1/login` for a JWT, then `POST /v1/my/api_keys` and `GET /v1/my/api_keys/<id>?reveal=true` to read the secret. `PATCH /v1/my/brands/<sid>` set company name, sender name and physical address. `POST /v1/my/brands/<sid>/prepare_sending {"subdomain":"orbit-builder-ad"}` returned `ready` immediately, with sender `hello@orbit-builder-ad.nitrosend.net`.
- **First send:** one transactional email via the SDK, `ns.messages.send({channel:'email', to:..., subject, html, body}, idempotencyKey)`. It went `queued` and then `sent` within seconds, and the "send receipt" email arrived about 5 s later.
- **Safe Mode:** `PATCH /v1/my/account {"safe_mode_enabled":true}` with the API key returned `403 {"message":"Not authorized"}`. The same call with the JWT returned 200 and `safe_mode_enabled: true`, at 12:44:15 UTC.
- **Held campaign (API key):** `POST /v1/my/contacts`, `POST /v1/my/lists`, `POST /v1/my/lists/<id>/contacts/bulk {"action":"add","emails":[...]}`, `POST /v1/my/campaigns`, `PATCH /v1/my/campaigns/<id>` (audience type `lists`, plain-text body with no merge tags), then `POST /v1/my/campaigns/<id>/send` with `deliver_at` 20 minutes ahead. The campaign went to `awaiting_approval` and the review email arrived at 12:47:30 UTC (subject "Review send request: Self test note").
- **Extraction:** My mailbox tool exposes the MAP part (`application/ld+json`) as a decoded attachment, not the raw `.eml`. I saved that decoded text byte for byte as `description.json`. I did **not** run `mailschema message` on a raw `.eml`, so that step was not exercised in this run.
- **Validate:** `npx mailschema@0.3.2 description description.json --contract contract.json`, with the contract downloaded from `https://mailschema.org/artifacts/map-0.3/contracts/campaign-send-approval-0.1.json`. Exact output (exit code 0):
  ```
  Valid MAP 0.3 description urn:uuid:1d148c4d-eba6-58a8-b5d9-d4361b149397
  sha-256:70e9b9cf026100cbe2c4427b5495ddd055ef96f9af46baa0582b59a8430f0c87
  ```
- **Recompute terms.version:** with `import { digest } from "mailschema"`, I removed `terms.version` from the parsed description and called `digest()` on the rest. Result: `sha-256:0ce53e0db136a9beaf4e2059452397bd7e0ff876088f0f323fb41551c446b7d1`, equal to the stated `terms.version`.
- **Decision:** declined, at 12:48:07 UTC, about 3 min 52 s after Safe Mode went on. It was `POST /v1/my/map/approvals/397 {"decision":"decline","version":"<terms.version>"}` with the JWT. The response was `state: declined`, `delivery_status: cancelled`. The test message was only to my own mailbox, so declining cost nothing and sent nothing. The decision receipt email arrived 3 s later.
- **Slowest step:** getting the decision through. An API key is refused for deciding, and the sign-in JWT is only returned in the `Authorization` response header of signup/login, which is easy to drop in a script. I also had to find the REST route for the decision in the OpenAPI spec.
- **Doc gap with repro:** `PATCH /v1/my/account {"safe_mode_enabled":true}` with an `nskey_live_...` API key returns `403 {"code":403,"message":"Not authorized","error":true}` with no hint that a signed-in JWT is required. A second small one: `PATCH /v1/my/campaigns/<id>` with `template_attributes.body` containing `<p>...</p>` returns `422 plain_text_contains_markup`. It is not clear from the field name or the docs that `body` is plain text unless `content_format` is set.
- **One change I would make:** return a message naming the accepted credential type on the 403 above, for example "this endpoint needs a signed-in session, not an API key".
